# Dataset Description and Data Dictionary

## 1. Overview and Study Scope
This dataset contains multimodal experimental tracking data, including Virtual Reality (VR) telemetry, physiological monitoring, speech recognition, electroencephalography (EEG), and system logs. 

---

## 2. Directory Structure
The data is organized hierarchically by experiment (`Expt2`, `Expt4`), then by subject. The two experiments do **not** carry the same modalities, so the per-subject file set differs between them: Expt2 records skin conductance (GSR) and has no EEG, whereas Expt4 records EEG (with its LiveAmp/LSL synchronisation stream) and has no GSR. The files common to both, plus the experiment-specific ones, are:

```
[Experiment_Name]/                             # Expt2 or Expt4
└── SUB[X]/                                     # Individual Subject Folder (e.g., SUB0, SUB1)
    │
    │   # Present in BOTH experiments:
    ├── SUB[X]__Control_Data__.json
    ├── SUB[X]__Data_Notes__.json
    ├── SUB[X]__Device_Data_DotNet_Azure_Speech_Rec__.json
    ├── SUB[X]__Device_Data_Unity_C_Sharp_Client_VR__.json
    ├── SUB[X]__Device_Descriptors__.json
    │
    │   # Expt2 ONLY (skin conductance / GSR):
    ├── SUB[X]__Device_Data_Phys_Monitoring_Arduino_v1__.json
    │
    │   # Expt4 ONLY (EEG and its LSL synchronisation stream):
    ├── SUB[X]__Device_Data_LiveAmp_LSL_Compatible_Univ__.json
    └── SUB[X]_markers_processed_eeg.npz
```

Consequently File 5 (`Phys_Monitoring_Arduino`) appears only under Expt2, and File 4 (`LiveAmp`) and File 8 (`markers_processed_eeg.npz`) appear only under Expt4.

## 3. File Registry and Schemas

### File 1: `SUB[X]__Control_Data__.json`
* Format: JSON Object
* Description: Contains experiment script execution logs and hardware/software command histories sent during the session.

| Key | Type | Description |
| :--- | :--- | :--- |
| log | Array (Objects) | Sequential log entries generated by the experimental control scripts. Each entry is an object, typically `{ "source", "msg", "timestamp" }` or `{ "interactive_settings_...", "timestamp" }`. |
| [Device_ID] | Array (Objects) | Dynamic keys, each an opaque device identifier (e.g. `SC91BBkyiIWxnJMipKYk`) whose human-readable name and schema are given in `Device_Descriptors`. The value is the time-stamped history of command objects sent to that device. |

---

### File 2: `SUB[X]__Data_Notes__.json`
* Format: JSON Object
* Description: High-level metadata regarding the experimental session and manual observations. The exact key set differs slightly between experiments: Expt2 files include `first_ten_block_stimulation_time` / `last_ten_block_stimulation_time`, whereas Expt4 files include `pressure` / `pressure_ratings` (tonic-pain cuff pressure and its calibration ratings).

| Key | Type | Description |
| :--- | :--- | :--- |
| exclude_trials | Array | Indices of trials/blocks to exclude from analysis. |
| exclude_reason | Object | Reason for each exclusion, keyed by trial/block index. |
| pain_side | String | Body side to which the painful stimulation was applied (`left` / `right`). |
| calibrate_ratings_amendment | Array | Manual corrections applied to the calibration-phase ratings. |
| ratings_amendment | Array | Manual `[block, value]` corrections applied to the recorded ratings. |
| ratings_amendment_reason | Object | Reason for each ratings amendment, keyed by block index. |
| rate_correction_factor | Array | `[block, factor]` scaling factors applied to collection-rate measures. |
| rate_correction_reason | Object | Reason for each rate-correction factor, keyed by block index. |
| first_ten_block_stimulation_time | Number | *(Expt2)* Stimulation pulse duration (ms) used for the first ten blocks. |
| last_ten_block_stimulation_time | Number | *(Expt2)* Stimulation pulse duration (ms) used for the last ten blocks. |
| pressure | Array | *(Expt4)* `[block, value]` tonic-pain cuff pressure applied per block. |
| pressure_ratings | Array | *(Expt4)* `[block, rating]` subjective rating of the applied cuff pressure. |
| other_notes | Array (Strings) | Qualitative observations, anomalies, or protocol notes recorded manually by the researcher during the session. |

---

### File 3: `SUB[X]__Device_Data_DotNet_Azure_Speech_Rec__.json`
* Format: JSON Array of Objects
* Description: Time-stamped numerical ratings recognised from the participant's spoken responses during the experiment, via the Microsoft Azure Speech SDK. Only the parsed numerical value is stored; no audio, no transcript, and no free-text speech content is retained.

| Key | Type | Description |
| :--- | :--- | :--- |
| recognition_val | Integer | The numerical rating (0–10) recognised from the number spoken by the participant. |
| timestamp | Numeric | Epoch timestamp (milliseconds) indicating when the value was finalised/recognised. |

---

### File 4: `SUB[X]__Device_Data_LiveAmp_LSL_Compatible_Univ__.json`
* Format: JSON Array of Objects
* Description: Lab Streaming Layer (LSL) synchronization data for the LiveAmp EEG amplifier, used to align timestamps across the recorded data streams.

| Key | Type | Description |
| :--- | :--- | :--- |
| last_trigger_on_client | Long Integer | Unix Epoch timestamp (milliseconds) of the last trigger received on the client side. |
| timestamp | Long Integer | System Unix Epoch timestamp (milliseconds) when the synchronization log was generated. |

---

### File 5: `SUB[X]__Device_Data_Phys_Monitoring_Arduino_v1__.json`
* Format: JSON Array of Objects
* Description: Physiological sensor streams captured via an Arduino microcontroller setup. Each top-level object is one batch received by the host, containing a host timestamp and an array of individual sensor `frames`. In this dataset only skin conductance (galvanic skin response, GSR) is present; although the hardware also supports heart rate and electromyography, those channels were not recorded here.

| Key | Type | Description |
| :--- | :--- | :--- |
| timestamp | Numeric | Host-side Unix epoch timestamp (milliseconds) at which the batch was received. |
| frames | Array (Objects) | The individual sensor samples in the batch. Each frame is `{ "timestamp", "skin_conductance" }`, where the frame `timestamp` is a device-side clock (distinct from the host epoch timestamp above) and `skin_conductance` is the raw GSR sample. |

---

### File 6: `SUB[X]__Device_Data_Unity_C_Sharp_Client_VR__.json`
* Format: JSON Array of Objects (Per-frame telemetry)
* Description: High-frequency spatial, interaction, and state data captured continuously from the Unity VR client environment.

| Key | Type | Description / Units |
| :--- | :--- | :--- |
| timestamp | Long Integer | Unix Epoch timestamp in milliseconds. |
| head_position | Array [X, Y, Z] | 3D spatial coordinates of the VR Headset (HMD). |
| head_rotation | Array [X, Y, Z, W] | Quaternion orientation vector of the VR Headset. |
| left_hand_position | Array [X, Y, Z] | 3D spatial coordinates of the Left VR Controller. |
| left_hand_rotation | Array [X, Y, Z, W] | Quaternion orientation vector of the Left VR Controller. |
| right_hand_position | Array [X, Y, Z] | 3D spatial coordinates of the Right VR Controller. |
| right_hand_rotation | Array [X, Y, Z, W] | Quaternion orientation vector of the Right VR Controller. |
| gaze_object | String | Name of the virtual object currently intersected by the user's gaze vector. |
| pickable_object | String | Name of the target object (fruit) entering basket. |
| pickable_object_attached | String | Name of the target object (fruit) currently grabbed/attached to the user's virtual hands. |
| user_action | String | Event triggers mapped to explicit user inputs (e.g., button presses). |
| board_command | String | System-level triggers or commands sent to the experimental dashboard. |
| slider_bar_value | Float | Normalized state (0.0 to 1.0) of virtual UI slider elements. |
| fruits_name | Array (Strings) | An array of fruit-object name strings, paired element-wise with `fruits_position`. |
| fruits_position | Array (Floats) | An array of 3D coordinates, paired element-wise with `fruits_name`. |
| deleted_fruit | String | *(All Expt4 subjects, and a subset of Expt2 subjects)* Name of a fruit object removed from the scene. |
| other_attached_object | String | *(All Expt4 subjects, and a subset of Expt2 subjects)* Name of a non-fruit object attached to the user's virtual hands. |

### File 7: `SUB[X]__Device_Descriptors__.json`
* Format: JSON Object
* Description: The device I/O schema, keyed by device ID (the same opaque identifiers used as keys in Control_Data); each entry describes one hardware/software interface used during the session. Caveat on data_to_report / data_to_control: these two schemas record the device's declared reporting and control capabilities. They are not used by the control software to parse or store the streams, so they were not always kept in sync with the acquisition code and can be out of date — in particular they may list more or fewer fields than were actually recorded: some declared fields were never captured, and some captured fields were later dropped because they were unused in the analysis code. Treat them as an approximate guide only (they are not intended to be parsed and referenced in any analysis); the authoritative list of fields actually present is the Device_Data_* file itself, documented per-device in Files 3–6 above.

| Key | Type | Description |
| :--- | :--- | :--- |
| [Device_ID] | Object | One entry per device, keyed by its opaque identifier. |
| &nbsp;&nbsp;name | String | Human-readable device name (e.g. "Unity VR Device"). |
| &nbsp;&nbsp;device_type | String | Device type/model identifier. |
| &nbsp;&nbsp;data_to_report | Object | Declared schema of the fields the device can report, mapping each field name to its data type. Indicative only — see the caveat above; the fields actually present are those documented for the corresponding `Device_Data_*` file (Files 3–6). |
| &nbsp;&nbsp;data_to_control | Object | Schema of the command fields that can be sent to the device (as recorded in `Control_Data`). |
| &nbsp;&nbsp;report_pack_order / control_pack_order | Object / null | Binary packing/ordering configuration for the reported and control streams. |
| &nbsp;&nbsp;visual_report / visual_control / visual_value_range | Object | Visualisation configuration used by the acquisition dashboard. |

---

### File 8: `SUB[X]_markers_processed_eeg.npz`
* Format: NumPy compressed archive (`.npz`), readable with `numpy.load`.
* Description: Preprocessed Electroencephalography (EEG) recording (32 EEG channels, 500 Hz sampling rate) stored as a set of plain NumPy arrays. In addition to the continuous signal, each file stores the processed event **markers** as annotation arrays (hence "markers_processed") — including trial start/end, pain-condition labels (e.g. `HighTonic`, `LowNoPressure`), stimulus triggers (`S 1`–`S 61`), and gaze/interaction events. The container holds only the arrays listed below and carries no acquisition- or subject-identifying metadata. It can be reconstructed into an MNE `Raw` object for analysis (see `core.individual_subject.npz_eeg_dataloader`).

| Key | Type | Description |
| :--- | :--- | :--- |
| data | Array (Float32) | Continuous EEG signal, shape `(n_channels, n_times)` = `(32, n_times)`, in Volts. Row order matches `ch_names`. |
| sfreq | Float | Sampling frequency in Hz (500.0). |
| ch_names | Array (Strings) | The 32 EEG channel labels (standard 10–20 electrode names, e.g. `Fp1`, `Cz`), ordered to match the rows of `data`. |
| ann_onset | Array (Float64) | Onset time (seconds from recording start) of each event marker. |
| ann_duration | Array (Float64) | Duration (seconds) of each event marker (`0` for instantaneous events). |
| ann_description | Array (Strings) | Label of each event marker — trial start/end, pain-condition labels (e.g. `HighTonic`, `LowNoPressure`), stimulus triggers (`S 1`–`S 61`), and gaze/interaction events. Paired element-wise with `ann_onset` / `ann_duration`. |
